06 · Error analysis

Observed misses, not hypothetical taxonomy

The ledger contains 4 critical-label mismatches and 25 supplemental value/scope changes. Causes are tied to real rows; prevention suggestions are engineering actions, not measured outcomes.

5

API interface omission

Cause observed: The first-pass api.types list omitted SOAP; The current official SOAP API guide identifies SOAP API and lists supported editions/permissions.

Prevention: Enumerate separately documented interfaces and webhooks/SOAP/GraphQL/SDK distinctions; do not assume the REST guide is the complete API surface.

Examples: Salesforce — api.types; Copper — api.types; Zendesk — api.types
5

API scope/detail completeness change

Cause observed: Expand the API detail to include the directly documented additional interface and avoid leaving a corrected type unexplained.

Prevention: Add an interface-completeness checklist to supplemental API review and ensure `api.types` changes are reflected in `api.details` with their exact limits.

Examples: Salesforce — api.details; Copper — api.details; Zendesk — api.details
1

Authentication-method omission

Cause observed: Attio's directly opened authentication guide supports OAuth 2.0, workspace API keys, Bearer tokens, and HTTP Basic (token as username, blank password). The first pass omitted Basic.

Prevention: Inspect the dedicated authentication guide and enumerate every documented wire-level method (including alternate HTTP authorization schemes) before normalizing the list.

Examples: Attio — auth_methods
2

Bounded MCP-search limitation clarified

Cause observed: Clarify that the unknown comes from bounded discovery and is not a NOT_FOUND determination.

Prevention: Use bounded-scope language for inconclusive official searches and keep UNKNOWN unless authoritative evidence supports availability or a scoped NOT_FOUND classification.

Examples: Copper — mcp.details; Podio — mcp.details
2

Credential-path conflation

Cause observed: Attio's official pricing page lists API/MCP on the Free tier and says no credit card is required; its hosted MCP uses user OAuth. The API-key path remains admin-only. The first-pass ADMIN_APPROVAL_REQUIRED label conflated the API-key route with all supported access paths.

Prevention: Model API-key, OAuth/MCP, and admin-issued paths separately; determine the record-level self-serve label from all viable documented paths rather than one credential route.

Examples: Attio — self_serve_status; Attio — self_serve_details
1

Credential-path nuance added

Cause observed: The earlier blocker could imply admin-key issuance is required for all integrations. The first-party MCP OAuth path is user-authorized; admin approval applies to workspace API keys.

Prevention: Write blockers per access path and distinguish OAuth user authorization from API-key issuance/admin controls.

Examples: Attio — buildability.blocker
1

MCP access constraint omitted

Cause observed: The first-pass blocker did not state the external ChatGPT subscription requirement or app-install permission documented by Pipedrive.

Prevention: Capture provider-account app-install permission and external client-plan requirements as distinct constraints; label which company owns each gate.

Examples: Pipedrive — buildability.blocker
1

MCP announcement/current-state conflict preserved

Cause observed: The initial details omitted a first-party server announcement. The later current official material inspected describes client use; it does not establish whether the announced server EAP is currently available. Preserve this conflict and UNKNOWN status.

Prevention: Track announcement dates and current setup pages side by side; an announced future/early-access feature remains UNKNOWN until current endpoint/setup is directly documented.

Examples: Zendesk — mcp.details
3

First-pass MCP false negative / unresolved value

Cause observed: The Amazon-owned repository directly documents a Local MCP for SP-API educational example. It establishes an available local MCP sample, not a hosted supported product. The first pass left status UNKNOWN because targeted MCP discovery was incomplete.

Prevention: Add a targeted first-party MCP discovery checklist and inspect first-party repositories/indexes; distinguish local examples, hosted products, and unsupported samples in separate fields.

Examples: Amazon Selling Partner — mcp.status; Pipedrive — mcp.status; Pipedrive — mcp.details
1

MCP product-versus-sample scope omission

Cause observed: The raw first pass left MCP unclassified and its details said no first-party status was assigned. The official Amazon-owned repository now documents a local educational MCP example; product-versus-sample scope must be explicit.

Prevention: Separate MCP presence from product support/hosting and credential requirements; quote repository caveats in the claim rather than collapsing them into a single availability label.

Examples: Amazon Selling Partner — mcp.details
2

outbound_webhook_capability_clarified

Cause observed: Clarify the directly documented outbound webhook automation while retaining REST as the API type and explicitly avoiding an unsupported claim of a standalone Webhooks API.

Prevention: Review examples in the full error table.

Examples: Freshdesk — api.details; Gorgias — api.details

Search/evidence scope note updated
